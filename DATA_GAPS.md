# TOPGUN · Мой день v0.2 — DATA GAPS

Статус: рабочий реестр вопросов для совместной встречи с Никитой.  
Назначение: явно отделить подтверждённые контракты прототипа от неподтверждённых полей и формул реальной аналитики TOPGUN / «Заботы».

## Правила работы с реестром

- Отсутствующий контракт не заменяется догадкой.
- Synthetic demo не закрывает DATA GAP реальной выгрузки.
- Пока разрыв открыт, зависимая метрика получает статус `DATA_GAP` и понятную причину.
- Разрыв закрывается только после фиксации ответа, владельца решения и даты подтверждения.
- Если определение понятно, но нужного поля нет, вопрос остаётся открытым до появления данных.

Статусы реестра:

- `OPEN` — определение или данные не подтверждены;
- `NEEDS_DATA` — определение обсуждено, но требуемого поля или периода данных нет;
- `NEEDS_CONFIRMATION` — решение сформулировано и ждёт подтверждения Никиты;
- `CONFIRMED` — контракт подтверждён и может быть перенесён в спецификацию и тесты.

## Подтверждённое только для synthetic demo

Следующие определения нужны для демонстрации приложения, но не закрывают DATA GAP реальной аналитики:

- одна строка равна одному визиту;
- `visit_id` уникален;
- `revenue_total = service_revenue + product_revenue`;
- `has_extra_service` содержит `Да/Нет`;
- `prebooked` содержит `Да/Нет`;
- anchor date равна максимальной дате набора;
- предыдущий период непосредственно предшествует текущему и имеет ту же длину.

## Форма закрытия разрыва

При подтверждении добавить к записи:

- принятое определение;
- точные исходные поля;
- формулу или правило преобразования;
- минимум один обычный и один пограничный пример;
- владелец решения;
- дата подтверждения;
- ссылка на тест, который фиксирует контракт.
